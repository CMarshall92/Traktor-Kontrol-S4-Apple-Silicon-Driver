Traktor Kontrol S4 MK1 Driver 2.8.0 — Apple Silicon

Native Instruments never shipped an arm64 driver for the S4 MK1. This installer replaces the Intel-only 2.8.0 driver with an arm64 build of the open-source S4 MK1 Revival driver:

  • S4 MK1 Audio Driver — a CoreAudio HAL plug-in that talks to the S4’s USB audio interface directly. Creates a Traktor Kontrol S4 audio device.
  • Traktor Controller Integration — a small identity shim kernel extension. Traktor Pro 4 looks for one exact IOKit class name; only the kernel can provide it. Without this, audio works in other apps but Traktor will not see the controller.

Reading this in Installer: do Phase 1 now if you want controller support, then continue with the install. If you only want the audio device, skip Phase 1 and uncheck Traktor Controller Integration in the Customize pane.

Requirements

  • An Apple Silicon Mac (M1 or later), macOS 11 or later.
  • Administrator password.
  • The S4 MK1 and a USB cable. About 15 minutes for the first install.

Phase 1 — One-time security change (recoveryOS)

This is only for the kernel extension. If you only want the audio device, skip this phase and uncheck that component in Phase 2.

  1. Shut down completely.
  2. Press and hold the power button until Loading startup options appears, then click Options → Continue and log in. Holding the power button is what enters One True Recovery (1TR), which bputil requires.
  3. Menu bar: Utilities → Startup Security Utility. Select your startup disk, choose Reduced Security, tick Allow user management of kernel extensions from identified developers, and click OK.
  4. Menu bar: Utilities → Terminal, then run these one line at a time:
bputil -n -k
csrutil enable --without kext
reboot

bputil asks for your admin user name and password. When it finishes, the Mac restarts.

What these do

  • bputil -n -k recreates the boot policy with third-party kext loading enabled (Permissive Security). Pass both flags in one invocation: -n rebuilds the policy and keeps only the options named in that same command.
  • csrutil enable --without kext keeps System Integrity Protection on but disables kext signature checking, which the ad-hoc-signed shim needs.

To stay on Reduced Security instead of Permissive, use bputil -k instead of bputil -n -k (the GUI step above already sets this). If the kext is later refused with a signature error, redo this phase with the exact pair above, or fall back to csrutil disable.

Optional confirmation before leaving recovery:

bputil -d
csrutil status

Phase 2 — Install

  1. Click Continue → Install and authenticate.
  2. In Customize, leave both checked:
    • S4 MK1 Audio Driver — the CoreAudio device.
    • Traktor Controller Integration — the kext Traktor needs.
  3. Let it finish. The installer removes the old x86_64 NI kext, MIDI plug-in and preference pane, installs and ad-hoc-signs the arm64 driver and kext, and tries to load the kext.

The post-install step will usually report that the extension is waiting for approval. That is expected; continue to Phase 3.

Phase 3 — Approve the extension and restart

  1. Open System Settings → Privacy & Security and scroll to Security. Click Allow next to the blocked CaiaqS4Shim message (authenticate).
  2. If no button appears, re-trigger the prompt from Terminal:
sudo kmutil load -p /Library/Extensions/CaiaqS4Shim.kext
  1. Restart. Booting with the S4 unplugged is fine and recommended for the first boot after installing.
  2. After login, plug in the S4.

Phase 4 — Verify

# 1. Kext loaded?
kmutil showloaded --bundle-identifier cc.moretti.s4native.CaiaqS4Shim

# 2. Did it match the S4?
ioreg -r -c com_caiaq_driver_TraktorKontrolS4_NIUSBUserClient -d 1 | grep -E 'Caiaq'

# 3. Audio device present?
system_profiler SPAudioDataType | grep -A6 -i 'S4'

# 4. Driver log (Ctrl-C to stop)
log stream --predicate 'subsystem == "cc.moretti.s4"'

Expected

  • kmutil showloaded lists cc.moretti.s4native.CaiaqS4Shim.
  • ioreg shows CaiaqArmedMask (goes non-zero once Traktor connects) and a rising CaiaqDelivered.
  • system_profiler shows Traktor Kontrol S4.
  • The log shows device open, fw …, then kext connected, then a reports digital … analog … line every ~5 seconds.
  • If the kext is not loaded, the log says kext not available … streaming without it and the reports line ends with (no kext); audio still works.

Then open Traktor Pro 4 → Preferences → Controller Manager. It should list Traktor Kontrol S4, not “Generic MIDI”. Set Traktor Kontrol S4 as the audio device in Traktor’s Audio Setup if it is not selected automatically.

Troubleshooting

SymptomCause / fix
Installer says Not an Apple Silicon Mac You are on an Intel Mac. This installer is arm64-only; use the Native Instruments 2.8.0 installer there.
Bad code signature / extension refused Redo Phase 1 with csrutil disable instead of csrutil enable --without kext, then restart.
Kext installed but not loaded Approve it in Privacy & Security, run sudo kmutil load -p /Library/Extensions/CaiaqS4Shim.kext, then restart.
No audio device in Audio MIDI Setup Run sudo killall coreaudiod, replug the S4, and check log stream for cc.moretti.s4.
Audio works, Traktor does not see the controller The kext is not loaded or approved. Audio and controller support are independent.
Mac loops at boot with the S4 attached Observed only with an early panicking kext build. Unplug the S4, boot, log in, then plug it in. If it recurs, uninstall the kext.
No sound from MAIN or PHONES Select Traktor Kontrol S4 as the output device. Output is 44.1 kHz only; inputs and multi-channel routing are not implemented yet.
ioreg shows the kext but CaiaqArmedMask stays 0 Traktor is not connected to the controller yet. Open Traktor and check Controller Manager.

Uninstall / restore security

Double-click Uninstall Traktor Kontrol S4 Driver.command in this folder, or do it manually:

sudo kmutil unload -b cc.moretti.s4native.CaiaqS4Shim
sudo rm -rf /Library/Extensions/CaiaqS4Shim.kext
sudo rm -rf "/Library/Audio/Plug-Ins/HAL/S4MK1.driver"
sudo kmutil clear-staging
sudo killall coreaudiod

Then restore security: shut down, hold the power button, Options → Continue, Utilities → Startup Security Utility → Full Security, and in recovery Terminal:

csrutil enable
reboot

Note: man bputil documents a one-way door. Full Security performs an online check, and on a Mac that is not fully up to date it may not be possible to set Full Security again. Reduced Security plus csrutil enable is the realistic restore point in that case. Decide before doing Phase 1.
